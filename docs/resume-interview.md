# 简历与面试讲解稿

## 简历项目名称

**FloraAgent：基于 LangGraph 与 DeepSeek 的定制花束 Agent 工作流系统**

## 简历描述

- 基于 FastAPI、React 和 LangGraph 设计并实现定制花束 Agent 工作流，支持需求解析、库存校验、方案生成、用户确认和商家制作单输出。
- 接入硅基流动 DeepSeek 模型完成自然语言需求结构化解析，将用户输入抽取为送礼对象、预算、花材、数量、风格和包装等字段。
- 设计库存校验、替代推荐、价格计算等工具函数，在 LangGraph 节点中约束 LLM 输出，避免生成库存不足或价格不可控的方案。
- 在花材、数量、包装和价格锁定后调用 LLM 生成花束方案标题、风格说明和花语解释，提升定制体验。
- 实现 Agent Trace 面板，可视化展示 LLM 调用、工具调用、兜底状态和工作流节点，提升项目可解释性和面试展示效果。

## 面试讲解思路

### 1. 为什么这是 Agent，不是普通 Chatbot？

普通 Chatbot 主要是对话回复，而这个项目有明确状态流转和工具调用。用户输入后，系统会解析需求、检查字段是否完整、查询库存、计算价格、生成方案、等待用户确认，并最终输出商家制作单。整个过程由 LangGraph 组织成可控工作流。

### 2. LLM 在项目里负责什么？

LLM 主要负责两件事：

- 将自然语言需求解析成结构化 JSON。
- 在后端约束条件下生成更自然的花束方案文案。

库存、价格、数量、可制作性不交给模型决定，而是由后端工具控制。

### 3. 如何避免模型胡编？

项目先通过库存工具锁定花材、数量、包装和价格，再把这些锁定结果传给方案生成模型。模型只能润色标题、风格、花语和备注，不能修改价格和花材清单。

### 4. 如果 LLM 调用失败怎么办？

后端保留规则解析和确定性方案生成兜底逻辑。LLM 不可用时，系统仍能完成演示流程，并在前端 Trace 中展示 fallback 状态。

### 5. 项目最有价值的技术点是什么？

最有价值的是把 LLM 接入真实业务流程，而不是简单调用聊天接口。项目体现了 Agent 编排、工具调用、业务约束、人机确认和可观测性，这些都是 AI 应用开发岗位比较看重的能力。

## 可继续扩展

- 接入真实图片生成 API。
- 使用 SQLite 或 PostgreSQL 持久化会话和订单草稿。
- 给 LangGraph 增加 checkpoint。
- 做商家后台库存维护页面。
- 增加 RAG 花语知识库。
- 增加单元测试和端到端测试。
